Backend:
- FastAPI works.

- Phase 2 unit tests pass.

- Existing UI already renders Experience DNA / visitor insights.
- The frontend still computes some or all insights locally.
- Existing local logic is useful as offline fallback.

PHASE 3 GOAL

Make the business dashboard use the real backend Experience DNA endpoint
when online, while preserving the existing local/on-device insight logic
as an offline fallback.

DO NOT redesign the app.
DO NOT introduce frameworks.
DO NOT migrate bookings/messages yet.
DO NOT modify Supabase migrations, RLS, indexes, authentication, or secrets.
DO NOT remove offline-compatible logic.

TASKS

1. Inspect before editing:
   - frontend/app.js
   - frontend/config.js
   - backend/main.py
   - backend/ai.py
   - existing tests

2. Find exactly where business insights / Experience DNA are currently:
   - computed
   - stored
   - rendered
   - refreshed

3. When the app is online and a valid business is selected:
   fetch:

   GET /api/businesses/{biz_id}/insights

4. Treat backend insights as authoritative while online.

5. Preserve the current local insight analyzer as fallback when:
   - navigator is offline
   - request fails
   - backend is unavailable

6. Do not break existing UI structure or styling.

7. Adapt backend response fields to the existing frontend view model
   rather than rewriting the entire UI.

8. The visible business insight experience should support, where present:
   - recurring visitor themes
   - evidence counts
   - evidence strength labels
   - opportunities / suggested experiments
   - supporting visitor evidence
   - uncertainty / weak-signal handling

9. Preserve human-in-the-loop behavior:
   AI may suggest an opportunity,
   but must never automatically:
   - change a listing
   - change pricing
   - create an experience
   - publish anything

10. Preserve multilingual evidence.
    English and Indonesian postcards from Supabase should be able to
    contribute to the visible Experience DNA.

11. Avoid fake certainty.
    If the backend says evidence is weak or insufficient,
    render that state instead of inventing a recommendation.

12. Do not remove the legacy local analyzer.
    Keep it clearly separated as:
    online backend source vs offline fallback source.

13. Add/update tests for:
    - successful online backend insights fetch
    - rendering backend insights
    - API failure fallback
    - offline fallback
    - no accidental mutation/publishing from AI suggestions

14. Preserve all Phase 2 tests.

15. Do not proceed to:
    - bookings migration
    - messages migration
    - IndexedDB rewrite
    - offline outbox
    - Whisper installation
    - auth
    - UI redesign
